# SDL3 DualSense extension

This is a project-local modification of SDL 3.4.16, not an upstream SDL feature. SDL retains its original zlib licence and copyright notices. SDL.cmake pins the release archive and hash; ApplySDL.cmake applies the reviewed patch or verifies that it is already present. A changed upstream integration point fails configuration.

The PS5 HIDAPI driver recognizes an application-specific eight-byte CNH1 command. Operation zero probes without writing to hardware, one enables experimental waveform output, and two disables it and expires pending waveform requests. Only PlayStation controllers 054c:0ce6 and 054c:0df2 over Bluetooth pass this gate. Regular applications and controllers retain the ordinary effect path unless explicitly enabled.

Operations three and four turn the controller microphone on and off with a 142-byte report 0x32 that carries only the 0x11 sub-packet, its first flag byte's bit 0 set for on. While on, waveform reports keep that bit set. A Bluetooth 0x31 input report whose second byte has bit 1 set carries a 71-byte Opus microphone packet at byte 3; the driver hands it to the function in the joystick's `SDL.joystick.chiaki.microphone` property and never reads it as pad input.

Operation one is idempotent: enabling an already enabled controller succeeds without another write, so a stream that regains focus keeps its Bluetooth route. The neutral effect that enters waveform mode is queued before the mode is set, so it is not subject to the waveform queue limit.

The extension accepts 142-byte report 0x32 carrying two sub-packets: 0x11 (header 0x91, length 4, flags 0x66, the pad's haptic buffer length twice and a counter) and 0x12 (header 0xd2, two 64-byte blocks, 64 stereo frames). The driver owns the shared four-bit sequence, the counter and the CRC. While enabled, ordinary state effects preserve native haptic selection and zero motor amplitudes. Both packet types use SDL's existing HID worker and device lifetime lock; no second raw-HID writer opens the controller.

The bridge paces waveform reports from the monotonic clock, one report of 64 frames every 21.33 ms, the audio's real rate at 3 kHz. Playing starts once 32 ms of audio is held, stops when the audio runs out, and resynchronizes rather than bursting after a stall of more than four reports. Submissions are refused when two device requests are outstanding, expire after 40 ms in the worker, are never coalesced as motor state and skip the worker's 10 ms fairness delay. Ordinary native-mode effects are capped at four. Already executing writes cannot be revoked.

No other library or service dependency is linked. The bridge converts little-endian signed 16-bit feedback at 3 kHz with bounded gain into signed eight-bit stereo frames, keeps at most 192 frames and discards a remainder older than 30 ms, so a slow link drops audio rather than accumulating latency. Adaptive trigger effects use SDL's existing 47-byte PS5 effect format.

Chiaki's PS5 session negotiation enables DualSense when an extended-feedback preference is enabled. Its haptic sink accumulates at most 512 bytes, drops malformed or stale data, and exposes 256-byte blocks plus latest trigger state to the bounded input poll. There is no per-packet dispatch to TCA or an unbounded main-queue callback chain. Console intensity settings and controller preferences scale feedback. Stop, focus loss and switching devices disable waveform mode and neutralize effects. Preferences remain off by default; unsupported waveform activation leaves standard rumble active.

Controls configuration remains payload version 1. These are additive optional fields: nativeHapticsEnabled, hapticStrength and adaptiveTriggersEnabled. Legacy documents decode them as false, 0.7 and false without rewriting saved mappings. Numeric validation still runs before persistence and stream activation.

On iOS SDL drives a DualSense through GameController, which has no raw reports. `sdl3-dualsense-mfi-triggers.patch` lets that driver take a 36-byte `CNT1` effect, a four-byte probe or a mode, positions, strengths, frequency and ten zone values per trigger, and applies it with `GCDualSenseAdaptiveTrigger`. The bridge converts the console's trigger effects into it. GameController has no microphone light, so the bridge reports that light as unsupported there.

## Verification boundary

Native tests cover PCM signs and gain, packet offsets, clock pacing against a simulated 3 kHz feed, trigger ordering, unsupported-device rejection, fragmented input, bounded overflow, expiry, cancellation and intensity routing. Swift tests cover preference decoding and round trips. Building and static analysis validate integration with the pinned SDL driver. Queue acceptance is not a HID-write acknowledgement, and neither proves actuator response. SDL's inherited worker does not return individual HID-write results to the app. The earlier 78-byte format was sent once per controller input report, about every 15 ms outside Game Mode and 7.5 ms in it, so 31 frames per report reached about 0.69 and 1.36 times real time. Clock pacing removes that dependency; its rate on hardware, simultaneous effects and physical latency remain unverified.

To validate on hardware, select the intended DualSense, connect it over Bluetooth, enable native haptics under Controls / Controllers / Haptics, save and start a new PS5 stream. Check waveform feedback, intensity/off settings, triggers, focus loss, disconnection and reconnection. Over USB the app does not use this patch for haptics: it plays the waveform through the controller's USB audio channels (`lib/bridge/haptic_audio.c`), and this patch only carries adaptive triggers and standard effects there.
